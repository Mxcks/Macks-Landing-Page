## Foundation Map content boundary (from the brief)

May be described as containing:

1. context and the accepted client brief
2. current-state analysis
3. findings tied to evidence
4. recommendations linked to findings
5. risks and constraints
6. prioritized next steps
7. source traceability back to the accepted intake

Must not be described as containing:

- Proposal pricing or payment terms
- agreement or deposit mechanics
- technical build execution
- developer tasks or GitHub issues
- source code or repository content
- client-specific work not supported by the analysis

The public page uses a condensed version (items 2 to 6) in the process step and the
Studio Foundation section. Items 1 and 7 are internal-facing and are not shown.

## Internal sequence (for orientation only, not for the page)

Engagement → accepted intake → Diagnostic / Foundation Map → relevant offerings →
Proposal → client decision → agreement and billing gates → delivery project.

The public story is deliberately simpler and must not contradict this.
